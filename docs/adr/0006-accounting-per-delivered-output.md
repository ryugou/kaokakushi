# ADR 0006: 勘定の単位を「受け渡した成果物」にする

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認済み（2026-07-30） |
| 関連 | [ADR 0005](0005-drop-tamper-resistance-backend-and-heavy-fault-tolerance.md)（機構の簡素化方針） |

## Context

従来設計は「同一素材の 24 時間以内の再書き出しは追加消費なし（grant）」を、写真そのものの同一性（`providerAssetKeyHash` / `contentFingerprint` / `SourceRecord`・`SourceAlias` の alias グラフ / 素材単位の消費済み台帳）で実現していた。

この扱いには2つの問題がある。第一に、勘定系で最も複雑な機構（ハッシュ2系統・alias 統合規則・不変条件 11 個・期限つき grant）を、稀なエッジケースの公平性のために維持している。第二に、時間窓ベースの免除は「保存→削除→レイアウトを変えて再生成」が 24 時間無料になる抜け道であり、**完成品 1 つ = 1 枠**という課金の建て付けと矛盾する。

## Decision

**枠（月間無料枠・トライアルクレジット）が数える単位は「受け渡した成果物」とする。素材の同一性は勘定に使わない。**

| 規則 | 内容 |
| --- | --- |
| 消費の計上 | 書き出しの確定（export-saga 手順 4）で計上する |
| 完了（＝枠の確定） | 生成後の**出力確認画面**で、利用者が**明示的な完了操作**を行った時点で「完了」となり、枠が確定する。完了操作の付近には「完了すると 1 枚として確定し、以降の作り直しは新しい 1 枚になる」旨を明示する |
| 保存・共有 | **完了後にのみ**行える。何度実行しても追加消費せず、成否は枠に影響しない（失敗しても出力は保持され再試行できる） |
| やり直しの免除 | **完了前**（出力確認画面）では「やり直す」で出力を破棄して編集へ戻れる。枠を追加消費しない（前の出力の差し替えとして扱う）。回数・時間の制限なし |
| 完了後の再生成 | 素材・プロジェクトが同じでも**新規消費**とする。時間窓による免除は設けない |
| バッチ処理の完了 | 全成果物の生成後、**結果一覧画面での完了操作 1 回**でバッチ内の全成果物が確定する（対象全出力の完了を同一トランザクションで確定する）。完了前は写真単位のやり直し（追加消費なし）ができる。一括保存・共有は完了後にのみ行える。クレジットの消費計上は従来どおり成果物単位 |

### 廃止するもの

| 廃止 | 理由 |
| --- | --- |
| `providerAssetKeyHash` / `contentFingerprint` と素材同一性の照合 | 勘定が素材の同一性を参照しなくなる |
| `SourceRecord` / `SourceAlias` の alias グラフと統合規則 | 同上 |
| `ExportGrant`（24 時間の再書き出し窓）と `freeMonthlyReexport` / `AuthorizedGrant` / `GrantAction` | 時間窓ベースの免除そのものを廃止 |
| 素材単位の消費済み台帳（トライアルの「同じ写真は再消費しない」判定） | クレジットは確定した成果物単位で消費する |
| バッチ選択時の「処理済み素材」分類 | 判定基盤（素材同一性）が消滅。選択枚数と残クレジットだけで判定する |

確認用の設定ハッシュ（`ProjectSettingsHash` / `PreviewRenderHash`）と `StampAssetHash` は勘定ではなく安全性・参照の基盤なので維持する。canonical-schema.md はこれらに必要な範囲まで縮小する。

## Consequences

- 完了前のやり直しは回数無制限で無料になり、従来（24 時間窓）より単純で一貫した説明になる: 「保存・共有するまで何度でも直せます。完成した作品は 1 枠です」
- **完了操作の直後に誤りへ気づいた場合も、やり直しは新規 1 枠になる。** 受容する。防ぐには時間窓が必要で、それは本 ADR が排除した抜け道と同じ構造のため。完了操作を明示ボタンにし、確定の意味を注記することで誤操作を減らす
- 同じ写真をピッカーで選び直した場合、処理済みかどうかの判定・表示は行わない（新しい加工として扱う）
- Paywall の `batch-credit` は「残クレジットを超える枚数を選んだ」で発火する。「新しい写真かどうか」の判定は存在しない
- 実装から alias グラフ・ハッシュ計算パイプライン・grant の寿命管理が消え、勘定は `OutputRecord` の状態参照だけで閉じる
