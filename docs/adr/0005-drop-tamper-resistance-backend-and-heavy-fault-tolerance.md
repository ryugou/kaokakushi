# ADR 0005: 改ざん対抗・自前バックエンド・高耐障害機構の廃止

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認済み（2026-07-30） |
| 置換 | [ADR 0004](0004-minimal-backend.md)（最小バックエンド）を全面的に置換する |

## Context

本アプリは C 向けで、大量ユーザを想定せず、サブスクで月数千円〜数万円の利益が目標である。実装は Claude Code 単独で行い、最短でのリリースを優先する。個人運用のためサーバの保守・監視に割ける工数はない。

従来設計は「利用者自身が端末内の DB・ファイルを直接改ざんする」攻撃に対抗する暗号基盤（HMAC 署名付き台帳、正準バイト表現、信頼時刻の多層防御）と、自前バックエンド（リモート設定・診断）、実機障害注入を伴う高水準の耐障害機構を持っていた。守られる価値は無料枠の月 5 枚とトライアル 5 クレジットであり、設計文書自身が「DB 書き込みを伴う攻撃は防げない」と認めていた。防御コストが守る価値に対して不釣り合いである。

## Decision

**提供機能・プラン・クォータ数値は一切変更しない。** 変更するのは強制と運用の仕組みだけである。

### A. 利用者自身による改ざんへの対抗機構を廃止する

| 廃止するもの | 置き換え |
| --- | --- |
| HMAC 署名付き台帳（`UsageLedger` / `SubscriptionState` / `ExportCommit` / `TrustedTimeState`）、HKDF 鍵導出、Keychain 鍵分離 | 平文で `app.db` に保存する |
| 正準バイト表現（canonical-schema.md）とゴールデンバイトテスト | 文書ごと廃止 |
| 信頼時刻（`TrustedTimeState` / 鮮度上限 / `TrustedUTCMonth` / 月次整合ロック / 時計改ざん検出） | 端末の UTC 年月を使う |
| `PriorUseEvidence` / `AppLifecycle` 痕跡検出 | 廃止 |
| `unverifiedLedgerWrites` / `ledgerWritesSinceConfigFetch` カウンタ | RevenueCat SDK の標準キャッシュ挙動に任せる |
| `WorkingSourceBinding` / `withVerifiedSource` の実体照合 | ファイルの存在確認のみ |
| 署名不正コミットの解消手順 | 署名の廃止に伴い消滅 |
| `UpgradeReason.ledgerBlocked` と `blocked(.ledgerIntegrityFailure)` | 発火条件が消滅するため削除 |

`contentFingerprint`（素材の同一性判定）は改ざん対抗ではなく機能（同一素材の直列化・alias 統合）の基盤なので**残す**。

### B. 自前バックエンドを持たない（v1 はサーバレス）

| 廃止するもの | 置き換え |
| --- | --- |
| Rust + Axum サーバ（`/v1/config`、診断エンドポイント） | 実装しない |
| リモート設定（署名 envelope、`configVersion` 規約、hard max 検証、期限切れ挙動、`RemoteConfigState`） | バンドル内定数。閾値変更はアプリ更新で行う |
| `killSwitches` | 廃止。障害時は緊急アップデートで対応 |
| 診断の自前収集 | Sentry のみ（クラッシュと未分類例外） |
| 更新誘導のバージョン自前配信 | iTunes Lookup API。誘導機能自体は残す |
| 強制更新（`minimumSupportedVersion`） | 配信手段が無くなるため v1 では持たない。更新誘導は常に任意の推奨とする |

### C. 耐障害機構を「課金者の成果物を失わない」水準まで簡素化する

| 廃止・縮小するもの | 置き換え |
| --- | --- |
| `ExportCommit` 7 状態 × 手順 12 段 × ロールバック 6 段 × 起動時復旧 14 段 | 状態 3〜4 個。非終端の中断は**すべてロールバックして枠を返還**する一律規則 |
| 実機 process-death 障害注入テスト基盤 | 状態機械のユニットテストで代替 |
| actor 再入・二重 resume・tombstone つき自前待機キュー | 単純な直列実行キュー 1 本（v1 は並列数 1） |

**残すもの**: 未受け渡し出力の保護（保存前に消えない、強制更新より受け渡し優先）、プライバシー境界（未加工の顔を端末外へ出さない、メタデータ許可リスト）、Core Image ゴールデン画像テスト、クォータ・プラン判定の純粋関数、DB 外部キー制約、履歴の寿命管理。

## Consequences

- 端末内データを直接書き換える利用者は無料枠・トライアルを回復できる。**受容する。** この規模では実在せず、被害上限は無料書き出し数枚である
- 端末時計の巻き戻しで月間枠をリセットできる。**受容する**
- クラッシュ時の会計は利用者有利に倒れる（最悪ケースは無料の再書き出し 1 回）
- サーバの構築・運用・監視・保守が不要になる。operations.md の大半と実装計画のサブプロジェクト 11 が消える
- 実装量はおおよそ 4〜5 割減となり、リリースまでの期間が短縮される
- 将来ユーザ規模が拡大し不正が実害になった場合は、本 ADR を改訂して署名台帳を再導入する（スキーマは加算的に拡張できる）
